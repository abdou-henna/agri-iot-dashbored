# Academic Thesis Builder Workspace — Smart Farm IoT Alfalfa Project

## Purpose

This workspace prepares the project for the `academic-thesis-builder` skill. It does **not** draft the thesis chapters. It defines the writing contract, source map, reference strategy, figure placement, chapter briefs, and execution order so that the later writing stage can produce a coherent, original, citation-aware Master thesis.

## Required thesis structure

The supervisor requires **three chapters only**:

1. Chapter 1 — Background and Theoretical Foundations
2. Chapter 2 — Related Works and Comparative Analysis
3. Chapter 3 — System Design, Implementation, and Evaluation

The thesis must also include front matter, abstracts, general introduction, general conclusion, future work, references, and appendices.

## Core instruction to future writing skill

Do not write from memory. Use the project assets, source map, figure plan, reference strategy, and chapter briefs in this workspace. Do not reuse old five-chapter plans from earlier project files. Do not copy prose from references or previous theses. Use references only for academic support, and reconstruct all writing around the implemented Smart Farm IoT project.

## Writing order

1. Write Chapter 1 completely.
2. Write Chapter 2 in two stages:
   - Stage 2A: related-work narrative by theme.
   - Stage 2B: comparative gap analysis and comparison tables.
3. Write Chapter 3 in two stages:
   - Stage 3A: hardware, firmware modes, communication, data storage, backend.
   - Stage 3B: dashboard, analytics, AI interpretation, deployment, validation, limitations.
4. Write General Introduction after the chapter plan is stable.
5. Write Abstract/Résumé/ملخص after all chapter content exists.
6. Write General Conclusion and Future Work last.

## Important boundaries

- Private files are not thesis sources and must not be cited or copied.
- Secrets, API keys, database URLs, WiFi passwords, private environment files, and credentials must not appear in the thesis.
- The thesis describes the system, not private deployment secrets.
- The thesis must not claim pH, NPK, ET, disease diagnosis, official salinity classification, or yield prediction as implemented features.
- Gemini is interpretation-only through the backend proxy.
- Deterministic analytics remain authoritative.
